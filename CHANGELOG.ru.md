# Changelog — dsh-docx-sidebar

## 0.3.0 — 2026-09-29

### Changed

- **Смена хостовой линии на DSH 0.2.0** (`main`, повышена из `compat/0.2.0`): `engines.dsh` и peer `@deepseek-ai/dsh-client-locale` меняются с `>=0.1.5-rc.1 <0.2.0-0` на `>=0.2.0-rc.1 <0.2.1-0` (rc-окно зафиксировано, пересмотр с 0.2.1). Чисто метаданная адаптация — потребляемая поверхность состоит сплошь из чистых caller-ов `ctx.get(...)` (с собственными локальными определениями интерфейсов); 0.2.0-rc.1 полностью совместим с плагинным API 0.1.7, ноль изменений кода. Линия 0.1.x (0.1.5/0.1.7) по-прежнему обслуживается замороженными ветками `compat/0.1.7` / `compat/0.1.5` (≤0.2.0).
- Дерево зависимостей обновлено под новую линию, lockfile перегенерирован; version/engines в `dsh.plugin.json` синхронно подтянуты к `package.json`.

### Документация (2026-09-29 — без повторной публикации)

- Ветвная структура приведена в порядок: `main` повышена до линии 0.2.0 (из `compat/0.2.0`); хостовая линия 0.1.x обслуживается замороженными ветками `compat/0.1.7` / `compat/0.1.5`. npm-мэппинг не меняется: `dsh-0.2.0` → эта линия, `dsh-0.1.7` / `dsh-0.1.5` → линия 0.1.x.
- Установка (эта линия): `dsh plugin --profile <profile> add dsh-docx-sidebar@dsh-0.2.0`.
- README дополнен установочно-совместимостной памяткой на пяти языках (de/fr/ru/es/it).

## 0.2.0 — 2026-09-23

Адаптация к ширине боковой панели: режим чтения масштабируется пропорционально ширине панели, с нижним и верхним пределами.

### Added

- **Адаптивное масштабирование по ширине** (`src/client/scale.ts` + `useReaderScale.ts`): из ширины контейнера выводится коэффициент, записываемый в CSS-переменную `--reader-scale`, базовый кегль `13px × scale`, основной текст целиком переведён на `em` и потому масштабируется вместе с ним. Базовая ширина: **коэффициент ровно 1 при 360px** (при нормальной ширине визуально полностью совпадает с 0.1.0), нижний предел **0.9**, верхний **1.15**.
- **Масштабируется только содержимое документа**: заголовки, абзацы, списки, код, примечания, таблицы и подписи к изображениям следуют коэффициенту; **инфострока, баннер предохранителя, состояния загрузки/пустоты держат фиксированный кегль** — меняющийся при перетаскивании разделителя текст интерфейса выглядел бы сбоем, а не адаптивностью.
- **Коэффициент квантован до двух знаков**: перетаскивание разделителя срабатывает только ступенями по 0,01, чтобы избежать перевёрстки на каждый пиксель.
- **Неизмеримая ширина откатывается к 1**: 0 / отрицательные / NaN / Infinity (первый кадр или аварийные отчёты) всегда рендерятся по базе, а не в крайних значениях — иначе при открытии вспыхнул бы микроскопический кегль.
- **Отступы переведены на `em`**: отступ буллитов `INDENT_EM = 1.08em`, при коэффициенте 1 равен прежним 14px.
- **Потолок ячеек таблиц 320px → 24.6em**: в узкой панели ячейки сужаются вместе с ней, а не выдавливают горизонтальную полосу прокрутки.

### Changed

- Изображения по-прежнему показываются в заявленных документом размерах с потолком только по ширине панели: растянуть растр сверх исходного размера в погоне за кеглем — только сильнее размыть, о воспроизведении речи нет.

### Tests

- 5 новых утверждений (всего 19): коэффициент равен 1 на базовой ширине, пределы и монотонность, откат при неизмеримой ширине, квантование до двух знаков, отступ совпадает с прежними 14px.

### Packaging

- **Первая публикация в npm**: `dsh-docx-sidebar@0.2.0`, dist-tags `latest` + `dsh-0.1.5`; 38 files / 75.8 kB, tarball shasum `1060a5e8bc35e0629cbd59b62d71620bfc5790b0`.
- Заявлено поле **`repository`**, указывающее на `drscrewdriver/dsh-docx-sidebar`. Список каталогизации связывает npm-пакет с репозиторием только если опубликованный пакет указывает на репозиторий.
- **Заявленные, но не существовавшие скрипты дополнены**: `publish-npm.ps1` и `migrate-profile.ps1` восстановлены из родственного репозитория (первый побайтово идентичен и не содержит имени пакета — имя и версия читаются из package.json); `fixtures` и `report` реализаций в этом репозитории не имеют, висячие декларации удалены.

## 0.1.0 — 2026-09-22

Первая версия: режим чтения `.docx` (без воспроизведения вёрстки), ноль рантайм-зависимостей.

### Added

- **Просмотрщик документов** (`registerFileViewer`, `exts: ['docx','docm']`, `fetchStrategy: 'custom'`): байты архива берутся из маршрута хоста `/sidebar/file`; ограждение путей рабочего пространства остаётся на стороне хоста.
- **Разбор** (`src/client/docx.ts`): уровни заголовков определяются **именем** стиля в `styles.xml` (`heading N`), `w:outlineLvl` как подстраховка, больше нет ошибок по конечной цифре id (`List1` — не заголовок); абзацы и строчное форматирование (жирный/курсив/подчёркивание/моноширинный/`w:tab`/`w:br`); `w:numPr`+`w:ilvl` → отступы списков; `w:tbl` → настоящие таблицы (ячейки больше не дублируются абзацами); колонтитулы → помеченные note-блоки.
- **Изображения**: байты извлекаются из архива → URL `blob:` (встроенные картинки лежат внутри zip, маршрута хоста для ссылки нет), освобождаются `revokeObjectURL` при выгрузке/переключении; неотрисовываемые форматы вроде EMF/WMF/TIFF → помеченный плейсхолдер, без молчаливых пустот.
- **Семь контуров предохранителя**: размер архива / суммарная распаковка / одиночная часть (три контурных затвора) + число блоков / текст в блоке / число изображений / одиночное изображение. Если объём изображения уже превышен в каталоге — **без распаковки, сразу пропуск**.
- **Не более одного предупреждения на измерение**: breaker внутри строит Map по reason, структурная дедупликация (у братского плагина случались двойные предупреждения одного измерения).
- **Тесты**: 14 утверждений, фикстуры — настоящие docx-zip, собранные на месте (CRC32 + центральный каталог + настоящий PNG), покрывают пути разбора, пять затворов и целостность плейсхолдеров zh/en; код выхода 0/1.

### Notes

- Намеренно не делается: пагинация/поля, воспроизведение шрифтов и кеглей, плавающие и закреплённые объекты, колонки, правки, примечания, восстановление нумерационных последовательностей, вёрстка формул. Интерфейс вверху подписан «Режим чтения — не воспроизведение вёрстки».
- Взаимных import с `dsh-opensheet-sidebar` (домен таблиц) нет: плагины самодостаточны; общий код выделят, когда появится третий потребитель.
